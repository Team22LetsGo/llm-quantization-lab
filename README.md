# LLM Quantization Lab

한국어와 영어에서 4bit LLM 양자화가 언어 모델의 다음 토큰 예측 품질에 미치는 영향을 비교하는 프로젝트입니다. 예비 실험 결과를 검토한 뒤, 언어별 성능 저하 분석(주제 1)과 한국어 품질 개선(주제 3) 중 하나를 후속 연구로 선택합니다.

## 실험 노트북

[`예비실험_Qwen2.5-1.5B_Colab.ipynb`](예비실험_Qwen2.5-1.5B_Colab.ipynb)은 Colab GPU에서 예비 실험을 실행하고 결과 표와 CSV를 저장합니다. 입력 모델과 데이터는 Hugging Face에서 내려받으므로 별도 입력 파일을 이 폴더에 준비할 필요는 없습니다.

### 실행 순서

1. Colab에서 GPU(T4) 런타임을 선택합니다.
2. 노트북의 첫 설치 셀을 실행합니다. CUDA가 보이지 않으면 설치를 중단합니다. 설치 중 CUDA PyTorch가 CPU 빌드로 바뀌지 않도록 현재 Torch 버전을 고정합니다.
3. PyArrow 복구 셀을 실행하고 런타임을 재시작합니다.
4. 재시작 후 import/GPU 확인 셀부터 아래로 순서대로 실행합니다. Google Drive를 연결하면 코드가 결과 폴더를 자동으로 만듭니다.

### 비교 조건

대상은 `Qwen/Qwen2.5-1.5B-Instruct`이며 조건은 다음 네 가지입니다.

- FP16 기준 모델
- 보정 데이터 없이 nearest rounding을 적용한 RTN 4bit
- 영어 Wikipedia 보정 데이터를 사용한 GPTQ 4bit
- 한국어 Wikipedia 보정 데이터를 사용한 GPTQ 4bit

보정 표본은 영어와 한국어 각각 128개, 최대 512 tokens입니다. 평가에는 한국어 Wikipedia와 WikiText-2 영어 test를 사용하며, 언어별로 3개 평가 묶음을 만듭니다. 각 묶음은 16개의 512-token 구간입니다.

## 평가와 해석

주요 지표는 Perplexity와 FP16 대비 상대 저하율입니다.

`D(%) = (양자화 모델 PPL / FP16 PPL - 1) × 100`

언어별 평가 말뭉치가 다르므로 한국어와 영어의 PPL 원점수를 직접 비교하지 않습니다. 각 언어 안에서 계산한 D와 한국어·영어 간 저하율 차이를 세 평가 묶음에서 함께 살펴봅니다. GPTQ 한국어 보정과 영어 보정의 차이도 한국어 평가에서 확인합니다.

결과를 본 뒤 주제 1 또는 3을 선택합니다. 예비 결과만으로 개선 효과를 단정하지 않으며, 혼합 정밀도 등 후속 실험은 선택된 주제에 맞춰 설계합니다.

## 출력과 현재 상태

노트북은 Google Drive의 `Team22/pilot_qwen15b` 폴더에 표본 JSON, 실행 환경 정보, 그룹별 PPL, 요약표, 언어별 저하율 차이, 한국어 보정 효과 CSV를 저장합니다.

현재 노트북은 작성되어 저장소에 포함됐지만, Colab T4에서 전체 실험을 끝까지 실행해 검증하지는 않았습니다. README의 비교 조건과 지표는 실험 계획이며, 결과를 나타내지 않습니다.
